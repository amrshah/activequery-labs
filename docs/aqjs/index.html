Understand the upstream JavaScript library through its source, distribution files and reproducible experiments.

Source boundary: This is an independent guide, not official API documentation. Confirm signatures and behavior in the exact release you intend to use.

What upstream describes

The AQJS README describes an ES2020-compatible, dependency-free library with a modular, event-driven approach. It also describes DOM/BOM update batching and event delegation. These are upstream claims; this guide does not yet assert independent performance or compatibility benchmarks.

Verified source orientation

The inspected source file ActiveQuery.js exports a named class: ActiveQuery. A minimal ES-module instantiation pattern is:

import { ActiveQuery } from "./ActiveQuery.js";
const aq = new ActiveQuery();

The constructor initializes an initlog array and attaches references to static helpers including DOM, nestedDOM, extend, isEmpty, exit and keepOn. It registers a readystatechange listener and executes function callbacks in initlog when the document reaches complete.

The static ActiveQuery.DOM(selector) helper returns null for no matches, a single element for one match, or a NodeList for multiple matches. nestedDOM(selector) is implemented for Element, Document, NodeList and HTMLCollection contexts.

Source inventory also includes instance predicates such as isArray, isArraySet, isObjectMap, isArrayLike, isString, isObject, isObjectLiteral, isFunction, isClass, isNodeList, isSet, isArgument, isJSON and isEmpty. Their detailed signatures and edge cases are not yet fully documented here.

Important: the constructor accepts an optional string argument that can install global and prototype selector helpers. That has global side effects. Do not use it casually; inspect the constructor implementation first.

Suggested learning path

  1. Read the current README and inspect the exported/public API in source.
  2. Check the latest release tag and compatibility requirements.
  3. Build a minimal page that loads the library and exercises one documented feature.
  4. Inspect event lifecycle, cleanup behavior and error handling.
  5. Measure performance in your own workload rather than assuming a library-level claim applies to every app.

Before adopting it

  • Pin a release instead of relying on a moving branch URL.
  • Confirm browser support and any required polyfills.
  • Understand how listeners and observers are registered and removed.
  • Test interaction with your framework or existing DOM code.
  • Preserve upstream license and attribution notices.

The source inventory is a starting point, not a complete API reference. See the research baseline; signatures, return values, side effects and edge cases still require method-by-method verification.
