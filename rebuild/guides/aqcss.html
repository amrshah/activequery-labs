Use AQCSS deliberately.

A source-led introduction to the ActiveQuery CSS utility system. Learn how to read its class families, reason about responsive rules and avoid treating a class name as a guarantee.

Home / Learn / AQCSS

1. The right mental model

AQCSS is a stylesheet, not a runtime layout engine. Its classes match selectors; the browser then resolves declarations through media-query eligibility, specificity, importance and source order.

Rule of thumb

A class prefix is a clue, not proof. Before relying on a utility, inspect its complete selector and later overrides, then verify the computed result at the viewport you care about.

2. Recognize the main class families

PurposeExamplesWhat to inspect
Flex layoutaq-flexon--*Display trigger, direction, alignment, gaps and responsive copies
Sizingaq-facet--*Width/height values, fraction tokens and min/max constraints
Spacingaq--margin-*, aq--padding-*Shorthand/longhand collisions and !important
Typographyaq-text--*Size, weight, alignment, casing and breakpoint variants
Positioningaq-affix--*Position mode, inset helpers, transforms and scroll container
Theme and bordersaq-swatch--*, aq-border--*Custom properties and interaction with other declarations

These are navigation families, not a promise that every token in a family works correctly. Use the class-token index and family maps to find exact declarations.

3. Read responsive prefixes correctly

The pinned stylesheet uses cumulative min-width utility blocks:

  • aq-t- rules become eligible from 600 CSS px.
  • aq-d- rules become eligible from 993 CSS px.
  • aq-s- rules become eligible from 1440 CSS px.

These blocks are cumulative, not mutually exclusive device ranges. At 1440px, the 600px, 993px and 1440px conditions can all match. aq-m- commonly names the baseline/mobile companion and is not the 600px breakpoint.

Verified defect: hide helpers

The mobile, tablet and desktop hide helpers contain malformed media-query expressions and are ignored by Chromium and Firefox. Do not use them as reliable visibility controls. The separate screen-hide helper at 1440px was verified to work.

4. A safe workflow for building a layout

  1. Start with semantic HTML and a small set of layout primitives.
  2. Find each intended token in the class-token index and inspect its complete rule.
  3. Check the family cascade map for competing declarations and responsive copies.
  4. Test the result at widths just below, at and above each relevant breakpoint.
  5. Record observed defects separately from intended design behavior.

Use the live playground to change one variable at a time. Keep a plain CSS fallback when a verified AQCSS token cannot express the required behavior reliably.
